# Current Hub endpoints

Generated by `cargo run -p morph-hub-api --example export_schemas`.
Source: `morph_hub_api::endpoints`; do not edit the table by hand.

The server dispatches this closed registry; the Rust SDK consumes its scopes and
mutation classification. Request/result types generate the linked structural
schemas. Domain validation still checks signatures, exact identifiers and value
conservation. Administrative archives are explicit public DTOs, separate from private
runtime snapshots. Import remains limited to empty bootstrap state.

Every API error uses [ApiErrorBody](hub-types/ApiErrorBody.json). Successful JSON
responses use HTTP 200. `/api/events` returns `text/event-stream` with EventView
data; connection/authentication errors before the stream use the same error body.
This stream is a bounded UI activity feed. `POST /api/event-log` provides durable,
source-bound typed event pagination under read permission; its body is a query,
not a mutation. See [delivery and retention rules](../runbooks/event-delivery.md).
`/api/metrics` returns Prometheus `text/plain`; the remaining bodies use JSON. Authentication is required unless
the server explicitly enables unauthenticated loopback. Scopes are exact grants,
not a hierarchy; restore also requires the server's explicit restore option.

Durable mutations require API version, idempotency key and reviewed revision
headers. Preview is read-only even though it uses POST. Health reports process liveness without store/RPC access. Readiness reports
explicit configured capability scopes (200 or 503); metrics are bounded authenticated text.
Readiness is observation, never signing or chain admission authority.
See [mutation/retry rules](../hub-api-mutations.md).
